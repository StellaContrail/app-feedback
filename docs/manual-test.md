# サイト共有の手動受入確認

README のローカルセットアップを行い、異なる Google アカウントを持つ通常の Chrome プロファイルを2つ使用します。アプリ登録、初期データ生成、イベント、招待は不要です。自動テストは、Google 認証済みのサイト共有参加者をテストデータとして用意し、Google OAuth 応答をモックします。実アカウントでのログイン成功や目視確認を証明するものではありません。

1. **ログインと共有範囲**: ツールバーアイコンから **Googleでログイン** を完了します。セッション・アプリ・招待・名前の入力欄がないことを確認します。ログイン画面、ログイン後の操作画面、投稿フォームに、同じサイトの全ユーザーでコメントを共有する説明があることを確認します。Google ログインを一度キャンセルして未ログインのままであることを確認し、その後ログインを完了して、署名済み情報に基づく Google アカウント名が表示されることを確認します。
2. **権限**: 通常の HTTP(S) サイトでツールバーアイコンを押し、**コメントを開く** を選びます。全サイトへの権限がないこと、新規タブに自動挿入しないことを確認します。Chrome の設定・内部ページは対象外です。新しいオリジンではユーザー操作と Chrome の activeTab 許可が必要です。
3. **A の投稿と B の閲覧**: A がボタン・リンクを選択して投稿します。選択時にフォーム送信や画面遷移が発生しないことを確認します。B は同じサイト・ページでコメントを有効にし、ピンを確認します。認証済みの3人目も、招待なしでそのページのフィードバックを閲覧できることを確認します。A のログアウト後も、B の一覧とピン詳細に A の Google 表示名が表示されることを確認します。ページの CSS が分離されたパネルに影響しないことを確認します。
4. **サイトとパス**: 同じオリジンの別パスを開きます。旧 `/app` ベースパスの外も対象とします。空の一覧が開き、そのパス固有のコメントを投稿できることを確認します。元に戻ると元ページのコメントだけが復元されることを確認します。別のオリジン、サブドメイン、スキーム、ポートではフィードバックが分離されます。クエリ文字列とフラグメントはページの区別に使用しません。ハッシュ・クエリによるルーターは未対応です。
5. **機密データ**: input、textarea、編集可能・非公開・非表示の領域とその子孫を選択できないことを確認します。テスト用の `site_feedback` 行だけを調べ、フォーム値、生の HTML、属性、Cookie、トークン、URL のクエリ・ハッシュが保存されていないことを確認します。コメントと通常の表示テキストは共有データです。個人情報や機密情報を含めないでください。
6. **ライフサイクル**: 2回開いてもパネルは1つだけになることを確認します。スクロール・サイズ変更に対象表示が追従すること、変更・消失した対象は推測で移動せず一覧に残ることを確認します。同一オリジンの再読み込み、SPA 遷移、戻る・進むでは、明示的に有効にしたタブだけが閲覧モードに復帰します。Escape で選択・下書きをキャンセルします。パネルを閉じると復元が無効になります。ホスト要素の削除でハンドラーを解除し、再有効化で新しいパネルを1つ作成します。別オリジンへの遷移で activeTab が失効し、再度ツールバー操作が必要になる場合があります。
7. **認証と移行**: トークンは24時間で期限切れとなり、ログアウトでコメントを削除せず無効化されます。再ログインで共有フィードバックが戻ることを確認します。旧セッショントークンでは再ログインが必要で、旧プライベートフィードバックがサイト共有に表示されないことを確認します。Google 設定がない場合はアクセスを許可しません。通常サイトや許可リスト外の拡張機能オリジンは CORS で拒否されます。期限切れは使い捨てレコードでテストし、実際の認証シークレットを使わないでください。
8. **移動とコピー**: 一覧項目をクリックすると対象を作動させずスクロール・強調表示することを確認します。ピンをクリックすると詳細が開き、×・Escape で閉じます。**一覧をコピー** は現在の正規化ページと読み込み済みコメントだけを出力し、認証情報や追加の DOM を含めません。クリップボード拒否・安全でない HTTP でエラーを表示することを確認します。

`pnpm test:browser` は、ログイン済みのテストデータで2プロファイルの Worker・D1・UI を検証します。`pnpm test:permissions` はさらに、分離した Xvfb ディスプレイとテスト専用のネイティブ拡張機能アクションショートカットを使い、許可リスト外のオリジンを検証します。実際の Google 同意や、人によるツールバークリックは検証しません。どちらもスクリーンショットの取得や拡張機能の公開は行いません。

## フィードバックの操作性（0.1.1）

対象を選び、表示される3つの選択肢から 不具合 / 提案 / よかった点 を直接選択します。初期選択は 提案 です。Tab と矢印キーで種類を選べ、フォーカスが見えること、種類の選択だけでは送信されないことを確認します。各種類を1件ずつ投稿し、赤・紫・緑の番号付きピンになること、一覧とピンのアクセシブルなラベルに種類がテキストとして残ることを確認します。長い Google 名や HTML のような名前もテキストとして描画され、一覧・詳細に収まることを確認します。クリップボード出力には引き続き投稿者名や Google アカウント情報を含めません。

## 拡張機能へのフィードバック（0.1.3）

未ログイン時に **この拡張機能にフィードバック** がなく、Google ログイン後に現れ、ログアウト後に消えることを確認します。ログイン後、ポップアップで開きます。フォームは初期状態で折りたたまれていることを確認します。短い報告を入力し、**GitHubで確認する** を選びます。新しいタブの遷移先が `StellaContrail/app-feedback/issues/new` で、入力文とインストール済みバージョンだけが設定されていることを確認します。GitHub アカウントと最終送信が必要で、Issue が公開される旨をポップアップに表示します。自動確認中にテスト用 Issue を送信しないでください。現在のサイト URL、Google 名、保存済みレビューが添付されないことを確認します。ポップアップを閉じて開き直し、下書きが永続化されないことを確認します。
