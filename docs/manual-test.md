# Milestone 1 manual acceptance

Status: two-profile **automated** Chrome UI/permission tests use seeded Google-associated app sessions. OAuth positive/negative tests use generated signing keys and mocked Google endpoints. Real Google consent and account login require the human flow described in `google-login.md`. On an origin without host permission, both reviewers were denied injection before the action and allowed afterward; same-origin SPA/reload retained activeTab, and cross-origin navigation revoked it. Human toolbar-click and visual checks remain unperformed. This checklist records remaining acceptance work; it does not imply any public deployment or extension publication.

Use the local setup in README, two normal Chrome profiles and an organizer-controlled review app. Use different Google accounts and one server-configured destination in both profiles. Keep the API on loopback. For a non-loopback app, register its exact origin/base path using a separate local bootstrap/database as appropriate; never add broad host permissions.

1. **User action / activeTab**: on a registered non-loopback HTTP(S) page, click the extension toolbar icon, join with **Googleでログイン** and complete Google consent, then choose **コメントを開く** followed by the page panel's **＋ コメントを書く**. Confirm a joined popup hides all join fields and has one main entry action. Confirm highlight follows the pointer. In `chrome://extensions` confirm no all-sites access is granted. Confirm opening an unrelated tab does not inject anything.
2. **A posts / B reads**: select a submit button and a link in A. Confirm selection neither submits nor navigates. Post a comment, reload the identical page in B, activate and confirm the numbered pin and exact comment appear. Page CSS must not change the popup/panel. B's credentials must differ from A's.
3. **Sensitive elements**: attempt to select a password input, textarea, contenteditable region and an element under `data-private`. Confirm they cannot be captured. Inspect local feedback rows (not auth headers or credential files) to verify they contain no input values, attributes, raw HTML, cookies or query/hash values.
4. **Isolation**: navigate B to another pathname under the registered base. Confirm A's route comments disappear; navigate back and confirm they return. A changed query/hash on the same pathname refers to the same route. Try an unrelated origin/outside-base path and a different session/app: feedback access must fail rather than display the old page's items.
5. **Lifecycle**: activate twice; confirm one panel. Change the selected DOM element's text/remove it: the comment remains in the list as unavailable. Scroll/resize and confirm pins move with their targets. Exercise history pushState and back/forward. Escape cancels selection/drafting while comments stay visible and ordinary clicks work. The **×** button stops display for this tab. Remove the `app-feedback-ui` host from the page DOM: ordinary clicks/submission must resume without pressing Escape, and reactivation must create one fresh UI. After one explicit activation, same-origin reload/back/forward should restore comments in viewing mode automatically. A new tab must not auto-inject; hiding the original tab must keep it hidden after reload. Out-of-base-path pages must not receive the UI. After a different origin revokes activeTab, a fresh toolbar click may still be necessary.
6. **Credentials / CORS**: in a disposable local DB, expire a participant, then a session; reads/writes must fail. Invite/admin secrets as bearer credentials must fail. Unlisted extension origins and an ordinary website Origin must get 403. Re-login only while the configured session/app remain valid. Confirm the popup needs no settings input, shows the Google account name, and logout returns to login while preserving comments after re-login.

Automated coverage already exercises session/origin/path separation, expiry, CORS preflight, validation/body limits, limits, hostile comments, click suppression, selector privacy, duplicate injection, host-removal cleanup, and stale reads/drafts/post completions before the SPA polling interval. Both browser suites also check that aggressive page CSS leaves panel styles unchanged and removing the host releases native form submission. The real Chrome smoke verifies A→D1→B with two independent profiles, a loopback fixture and actual extension messages. `pnpm test:permissions` also verifies action-granted activeTab on a non-allowlisted origin using a temporary action shortcut and isolated Xvfb display. It checks the browser permission, then injects via a trusted popup-page message; it does not claim a human toolbar-click, visual ergonomics or compatibility result in the intended external app.

7. **Google login requirement**: configure a Web application OAuth client/redirect and the server-only secret, then sign in with the real Google chooser. Cancel it once: no participant should be issued. Complete it: reading/writing should work only with a valid invite. Reload/reopen the extension with a pre-Google token: joining must be required again. Leaving the app must reject the old app token while preserving comments. Never paste a Google password, client secret or ID/access token into logs/chat.

## Comment navigation and copying

1. Put a reviewed element below the viewport, click its list comment, and verify scrolling/highlighting without submitting a form or following a link. Confirm the highlight follows scroll/resize. Keyboard users can Tab to comments and activate with Enter/Space.
2. Click a numbered pin: its full comment/category appear in a nearby card and its list row is selected. Close with × or Escape. After removing/changing the target, its comment stays available with an unavailable notice; clicking must never jump to a different element. Route changes clear the detail and highlight.
3. On HTTPS or localhost click **一覧をコピー** once, paste into an editor, and verify valid JSON for only the current route, including comment/category/saved target information. Check that no invite, app bearer token, Google data or extra live DOM/form values were added. The extension never sends the export to an AI. Browser clipboard denial/insecure HTTP must produce a helpful error.
