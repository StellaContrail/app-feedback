# Site-sharing manual acceptance

Use the local setup in README and two normal Chrome profiles with different Google accounts. No app registration, bootstrap, event or invite is required. Automated tests use seeded site-sharing Google-associated participants and mocked Google OAuth responses; they do not establish a successful real-account login or visual review.

1. **Sign in and sharing scope**: click the toolbar icon and complete **Googleでログイン**. Confirm no session/app/invite/name inputs appear. The login screen, joined action and composer explain that comments are shared with all users of the same site. Cancel Google once and remain signed out; then complete login and see the signed Google account name.
2. **Permissions**: on any normal HTTP(S) site, click the toolbar icon and **コメントを開く**. There must be no all-sites permission. A new tab must not inject automatically. Chrome settings/internal pages are unsupported. A new origin requires a user action and Chrome's activeTab grant.
3. **A posts / B reads**: A selects a button/link and posts. Selection must neither submit nor navigate. B opens the same site/page, enables comments and sees the pin. A third authenticated user should also see that page's feedback, without an invitation. Confirm A's Google display name appears in B's list and pin detail, including after A logs out. Page CSS must not affect the isolated panel.
4. **Sites and paths**: use another path on the same origin, including one outside the old `/app` base. It should open an empty list and allow its own comments. Returning restores only the original page's comments. Other origins, subdomains, schemes and ports have separate feedback. Query strings and fragments do not distinguish pages. Hash/query routers remain unsupported.
5. **Sensitive data**: inputs, textareas, editable/private/hidden regions and their descendants must not be selectable. Inspect only test `site_feedback` rows to confirm no form values, raw HTML, attributes, cookies, tokens or URL query/hash data are stored. Comments and ordinary visible text are shared data; do not put personal or confidential content in them.
6. **Lifecycle**: opening twice creates one panel. Scroll/resize follows the target. Changed/missing targets stay in the list without a guessed jump. Same-origin reload, SPA navigation and back/forward restore viewing mode only in an explicitly enabled tab. Escape cancels selection/drafting. Closing the panel disables restoration. Host removal releases handlers; reactivation creates one fresh panel. Cross-origin navigation can revoke activeTab and require another toolbar action.
7. **Auth and migration**: tokens expire after 24 hours and logout invalidates them without deleting comments. Re-login restores shared feedback. An old session token must require a fresh login, and private legacy feedback must not appear in site sharing. Missing Google configuration fails closed. Ordinary website origins and unlisted extension origins fail CORS. Test expiry with disposable records, not live auth secrets.
8. **Navigation and copy**: click a list item to scroll/highlight without activating the target. Click a pin to show its detail; ×/Escape closes it. **一覧をコピー** exports only the current normalized page and already loaded comments, without credentials or extra DOM. Verify clipboard denial/insecure HTTP gives an error.

Run `pnpm test:browser` for two-profile Worker/D1/UI coverage with seeded login. `pnpm test:permissions` additionally uses an isolated Xvfb display and a test-only native extension action shortcut on a non-allowlisted origin. These do not exercise real Google consent or a human toolbar click. Neither takes screenshots or publishes an extension.

## Feedback usability (0.1.1)

Select a target, then choose 不具合 / 提案 / よかった点 directly from the three visible options. 提案 starts selected. Tab and arrow keys must select categories with a visible focus indicator; choosing a category must not submit. Post one of each and confirm red / purple / green numbered pins, with the category still available as text in the list and the pin's accessible label. Long or HTML-like Google names must render as text and fit the list/detail. The clipboard export continues to omit author names and Google account information.

Type a short report and choose **GitHubで確認する**. Check that the new tab targets only `StellaContrail/app-feedback/issues/new`, with the typed text and installed version prefilled.
